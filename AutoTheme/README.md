# 巨作一键整理 · Auto Theme 0.2.0

文明 6 单机 UI Mod。点击一次，扫描自己整个巨作面板：先尝试新增主题化建筑，再改善剩余藏品的存放位置。

## 安装与使用

解压 `dist/AutoTheme-0.2.0.zip`，将其中的 `AutoTheme` 文件夹复制进游戏 `Mods` 目录。从源码安装则复制 `src/AutoTheme/`，不要复制包含 `src`、`dist` 的整个项目目录。

- Windows：通常为 `文档\My Games\Sid Meier's Civilization VI\Mods`。
- macOS：通常为 `~/Library/Application Support/Sid Meier's Civilization VI/Mods`。

升级时用新文件夹替换旧 `AutoTheme` 文件夹，保持只安装一份；Mod ID 沿用原版。旧 0.1.0 安装包仅作为历史版本保留。

在「额外内容 → 模组」启用「巨作一键整理 / Auto Theme」。进入自己的回合，点击屏幕左侧「一键整理巨作」，等待结果。它是一次性操作，获得新藏品后可以再次点击，不会每回合自动重排。

整理期间点击「停止整理」，会等待已经提交的一笔交换结束后停止续派。已完成的交换保留，不自动回滚。整理时请等待完成后再手动移动藏品。

## 覆盖范围

读取面板使用的实际建筑、槽位和作品数据，不使用博物馆或作品类型白名单。

| 内容 | 处理方式 |
| --- | --- |
| 艺术品、考古文物 | 根据当前主题规则组合，保留冷却和满槽限制 |
| 遗物、宗教或英雄模式新增遗物 | 读取实际作品类型、合法槽位及建筑主题规则 |
| 著作、音乐 | 可在普通建筑与奇观间调配，参与对应主题 |
| 公司产品、大报恩寺陶瓷及其他特色产品 | 根据当前产品类别、主题规则及合法产品槽整理 |
| 宫殿、神庙、博物馆、奇观、商业与其他建筑 | 有巨作槽位即纳入扫描；普通储存建筑可提供藏品或中转空间 |
| 混合槽位、额外槽位 | 逐槽读取实际类型，按槽位组匹配规则，不再限制为六槽 |
| 其他 Mod 新增类型 | 只要通过标准巨作表、槽位及移动机制实现，同样读取并检查合法性 |

这里管理的是**已经在巨作面板中的藏品**。不自动生产公司产品、挖掘遗址、选择考古来源或交易其他文明的巨作。

## 主题化与存放规则

1. 保留游戏报告已经主题化的建筑，包括由文明能力自动主题化的建筑。不会拆借这些组合。
2. 读取当前 `Building_GreatWorks`，按同类、同年代、不同人物、不同来源玩家等规则匹配。混合建筑逐槽位类型应用相应规则。
3. 作品身份优先使用 `GreatPersonIndividualType`，没有时使用原生创作者信息。因此 HD 将产品人物身份设为类别时，会按类别区别，而不是把产品名称或每件产品的编号当作不同类别。
4. 读取 `GREATWORK_ART_LOCK_TIME`，固定不能移动的艺术品；考古文物转移要求来源与目的建筑都满槽。
5. 在内存中先规划合法交换顺序。直接交换不合法时，可先将被占用的藏品移到兼容槽位，再置入目标作品。未找到合法顺序的组合跳过并报告，不会先执行半套失败计划。
6. 完成主题安排后，再对其余藏品做有严格评分改善的合法交换。优先释放通用槽位、使用专用槽位，并考虑可识别的城市收益和旅游加成。

普通存放评分支持静态巨作产出、城市产出偏好、建筑提供的无条件 `MODIFIER_SINGLE_CITY_ADJUST_TOURISM` / `MODIFIER_SINGLE_CITY_ADJUST_RELIGIOUS_TOURISM`，以及巨作提供的无条件 `MODIFIER_SINGLE_CITY_ADJUST_CITY_YIELD_MODIFIER`。只有明确识别的效果才计分；不猜测任意条件 Modifier 或自定义 Lua 的收益。

这是**有界启发式整理**，不保证全局最优或完整的文化胜利收益最优。主题搜索有节点预算，普通存放最多规划 64 笔改善交换；达到上限会显示提示。复杂多步环形腾挪可能被跳过。覆盖整个面板表示参与读取和合法调配，不表示任意第三方脚本的特殊主题规则都已经适配。

## 执行与和而不同兼容

通过原生 `PlayerOperations.MOVE_GREAT_WORK` 请求交换，不直接创建巨作、修改归属或强加主题奖励。每次只提交一笔，确认所有监控槽位的实际内容后才继续；结束时用游戏的 `IsBuildingThemedCorrectly` 验证主题结果。

手动移动藏品、建筑或城市变化、回合结束、交换未生效或接口异常时停止。实际规则与计划不一致时显示错误，不会声称主题化成功。已完成的合法交换保留；游戏正常保存其位置，读档不会自动重启整理。

和而不同方面，已核对公开本体及行业与公司扩展源码：产品类别身份、产品主题化槽位、大报恩寺陶瓷、奇观和宗教建筑等均通过当前加载的数据读取。没有复制或替换 HD 界面、修改其数据库，也不依赖其他本地 Mod。

**0.2.0 尚未实机验证。** 开发机没有文明 6，公开源码也可能落后于工坊当前版本，因此还不能保证当前 HD 组合的游戏内效果。仅支持单机，不支持热座/联机；不要同时开启其他自动巨作整理功能。

## 已做验证与最短试玩

本地已通过 Lua 语法、XML、清单和本地化引用检查，以及临时 Lua 环境中实际规划、调度源码的执行检查。没有添加测试框架或 CI。

覆盖：原有艺术品/文物、冷却与未满文物馆、原主题保留、串行异步交换、停止/拒绝/手动改动/回合结束，以及以下扩展场景：

- HD 风格的产品类别身份，大报恩寺混合产品类别主题。
- 八槽著作奇观、宗教遗物建筑、混合艺术/音乐/著作槽位。
- 遗物占用通用槽位时，先腾挪再接收专用艺术槽中的作品。
- 没有主题目标时，将具有已知产出加成的产品调整到更适合的城市。
- 动态新增作品类型参与专用槽位整理。
- 重复点击稳定，藏品总数不变，无丢失或重复。

模拟不验证游戏 API 本身、真实 UI 或存档序列化。最短实机路径是在实际 HD 模组组合下保存游戏后点击按钮，检查大报恩寺/产品槽、遗物、著作音乐奇观及考古馆；随后检查原主题组合、藏品总数、停止按钮，再保存读档验证位置。错误排查查看 `Logs/Lua.log` 中的 `[AutoTheme]`，加载问题也查看 `Modding.log`。
